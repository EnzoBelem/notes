# Docker Swarm: conceitos e comandos básicos

#Docker

O **Docker Swarm** é o orquestrador nativo do Docker. Ele transforma várias máquinas com Docker em um único cluster, gerenciado pelo próprio Docker CLI, sem instalar nada além do Docker.

## Conceitos

- **Node**: cada máquina (ou instância do Docker) participante do cluster.
- **Manager**: node que gerencia o cluster, agenda tarefas e mantém o estado. Em produção usa-se um número ímpar (3 ou 5) para manter o quórum do consenso Raft.
- **Worker**: node que apenas executa as tarefas.
- **Service**: a definição do que deve rodar (imagem, réplicas, portas). O Swarm garante que o estado desejado seja mantido.
- **Task**: uma instância (um container) de um service, alocada em um node.
- **Stack**: um conjunto de services descritos em um arquivo Compose e implantados juntos.

## Criar o cluster

```bash
docker swarm init --advertise-addr <IP-DO-MANAGER>   # no manager; imprime o comando de join
docker swarm join --token <TOKEN> <IP-DO-MANAGER>:2377  # nos workers
docker swarm join-token worker                       # reexibe o token de worker
docker node ls                                       # lista os nodes (rodar no manager)
```

## Services

```bash
docker service create --name web --replicas 3 -p 80:80 nginx   # cria o service
docker service ls                                              # lista services
docker service ps web                                          # tasks e em qual node estão
docker service scale web=5                                     # muda o número de réplicas
docker service update --image nginx:1.27 web                   # rolling update
docker service logs web                                        # logs do service
docker service rm web
```

Se um container cair ou um node falhar, o Swarm recria as tasks automaticamente (autorreparo). Conexões na porta publicada são balanceadas entre as réplicas pela *routing mesh*, em qualquer node do cluster.

## Stacks

Um arquivo Compose pode ser implantado direto no cluster. A chave `deploy` só tem efeito no Swarm:

```yaml
services:
  web:
    image: nginx
    ports:
      - "80:80"
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 10s
```

```bash
docker stack deploy -c docker-compose.yml minha-stack
docker stack ls
docker stack services minha-stack
docker stack rm minha-stack
```

## Redes e segredos

- Redes do tipo **overlay** conectam containers de nodes diferentes: `docker network create -d overlay minha-rede`.
- **Secrets** guardam dados sensíveis criptografados no cluster: `docker secret create db_password -`. Dentro do container ficam em `/run/secrets/<nome>`.

## Sair do cluster

```bash
docker swarm leave           # no worker
docker swarm leave --force   # no último manager, desfaz o cluster
```
