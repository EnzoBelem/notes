# uv

#Python

O **uv** é uma ferramenta de gerenciamento de Python e de pacotes escrita em Rust, criada pela Astral (a mesma empresa do [[4.4. ruff]]). A proposta é consolidar em um único executável o que antes exigia várias ferramentas. Ele substitui:

| Ferramenta | Função | Equivalente no uv |
| --- | --- | --- |
| `pyenv` | Gerenciar versões do Python | `uv python` |
| `virtualenv` / `python -m venv` | Criar ambientes virtuais | `uv venv` |
| `pip` | Instalar pacotes | `uv pip` ou `uv add` |
| `pip-tools` | Travar dependências (`pip-compile`) | `uv pip compile` ou `uv lock` |
| `pipx` | Rodar e instalar CLIs isoladas | `uvx` / `uv tool` |
| `poetry` | Gerenciar projeto, dependências e build | `uv init`, `uv add`, `uv sync` |
| `twine` | Publicar pacotes no PyPI | `uv build` + `uv publish` |

O desempenho informado pelo projeto é de **10 a 100 vezes** superior ao do `pip`. Como ele funciona por dentro está em [[4.6.1. Como o uv funciona]].

Instalação (Linux/macOS):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version
uv self update    # atualiza o próprio uv (quando instalado pelo script)
```

## 1. Substituindo o `pyenv`: versões do Python

O uv baixa e gerencia versões do Python diretamente, usando executáveis pré-compilados. Não há compilação demorada nem é preciso manter o `pyenv` instalado.

```bash
uv python install 3.10 3.11 3.12   # instala várias versões
uv python list                     # versões disponíveis e instaladas
uv python pin 3.11                 # cria/atualiza .python-version no projeto
```

Executar algo pontualmente com outra versão ou implementação (o uv baixa sob demanda se ela não estiver instalada):

```bash
uv run --python pypy@3.8 -- python
uv run --python 3.12 -- python --version
```

## 2. Substituindo o `pip` e o `virtualenv`

O uv oferece duas abordagens: a **interface compatível com o `pip`**, para ganhar velocidade sem mudar projetos existentes, e o **modo de projeto**, no estilo Cargo/Poetry.

### Opção A: interface `uv pip` (fluxos com `requirements.txt`)

Você mantém os mesmos arquivos e comandos, só que mais rápidos.

```bash
uv venv                                   # cria o .venv em milissegundos
uv pip install requests                   # equivalente ao pip install
uv pip sync requirements.txt              # instala exatamente o que está no arquivo
uv pip compile requirements.in --universal --output-file requirements.txt
```

- `uv pip sync` deixa o ambiente **idêntico** ao arquivo: instala o que falta e **remove** o que não está listado.
- `uv pip compile` é o equivalente ao `pip-compile`. A flag `--universal` gera uma resolução que vale para várias plataformas e versões do Python, em vez de só para a máquina atual.
- Em um ambiente virtual criado pelo uv não há `pip` instalado por padrão. Use `uv pip`, ou `uv venv --seed` se precisar do `pip` lá dentro.

### Opção B: gerenciamento de projeto (`pyproject.toml` + `uv.lock`)

Para projetos novos ou migrações. Os metadados ficam no [[4.5. TOML e pyproject.toml]] e as versões exatas no `uv.lock`.

```bash
uv init meu-projeto      # cria pyproject.toml, .python-version, README.md, .gitignore e um repositório Git
cd meu-projeto
```

O código inicial depende da versão do uv: as mais antigas geram um `main.py`, e as mais recentes (testado na 0.12) geram um pacote em `src/meu_projeto/`. Use `uv init --bare` para criar só o `pyproject.toml`, `--lib` para uma biblioteca e `--vcs none` para não inicializar o Git.

Adicionar dependências:

```bash
uv add fastapi                  # dependência de produção -> [project].dependencies
uv add --dev ruff pytest        # dependência de desenvolvimento -> [dependency-groups].dev
uv remove fastapi               # remove
```

O `uv add` cria o `.venv` automaticamente, edita o `pyproject.toml` e gera ou atualiza o `uv.lock`.

Executar comandos no ambiente do projeto:

```bash
uv run pytest
uv run python main.py
```

**Não é preciso ativar o `.venv`** (`source .venv/bin/activate`): o `uv run` já executa no ambiente correto, e antes disso sincroniza o ambiente com o `uv.lock`.

> Para o `fastapi dev` funcionar, o FastAPI precisa estar instalado com o extra `standard`: `uv add "fastapi[standard]"`, e então `uv run fastapi dev`.

Sincronizar em outra máquina, em CI/CD ou em produção:

```bash
uv sync               # cria/atualiza o .venv conforme o uv.lock
uv sync --locked      # falha se o uv.lock estiver desatualizado em relação ao pyproject.toml
uv sync --frozen      # usa o uv.lock como está, sem checar se está atualizado
uv sync --no-dev      # ignora as dependências de desenvolvimento
```

Sem `--locked` ou `--frozen`, o `uv sync` **atualiza o `uv.lock` se ele estiver defasado**. Em CI e em imagens Docker, prefira `--locked` (ou `--frozen`) para garantir que o que foi testado é o que será instalado.

Outros comandos úteis do modo de projeto:

```bash
uv lock                       # gera/atualiza o uv.lock sem instalar
uv lock --upgrade-package x   # atualiza só um pacote
uv tree                       # árvore de dependências
uv build                      # gera sdist e wheel em dist/
uv publish                    # publica no PyPI
```

## 3. Substituindo o `pipx`: ferramentas CLI isoladas

Para rodar linters, formatadores ou utilitários sem poluir o ambiente do projeto nem o Python do sistema.

```bash
uvx ruff check .              # executa sem instalar antes (uvx é alias de uv tool run)
uvx pycowsay "olá"
```

O uv cria um ambiente temporário no cache, executa a ferramenta e o descarta (as execuções seguintes reaproveitam o cache).

Instalar de forma persistente, cada ferramenta em seu próprio ambiente isolado:

```bash
uv tool install ruff
uv tool list
uv tool upgrade ruff
uv tool uninstall ruff
uv tool update-shell          # garante que o diretório dos executáveis está no PATH
```

## 4. Scripts avulsos (metadados inline, PEP 723)

Para automações ou scripts utilitários que precisam de bibliotecas externas sem criar uma pasta de projeto inteira.

1. Declare as dependências no próprio arquivo:

   ```bash
   uv init --script automacao.py        # cria o script já com o bloco de metadados
   uv add --script automacao.py requests pandas
   ```

   Isso injeta no topo do arquivo um bloco TOML em comentários:

   ```python
   # /// script
   # requires-python = ">=3.12"
   # dependencies = [
   #   "requests",
   #   "pandas",
   # ]
   # ///
   ```

2. Execute:

   ```bash
   uv run automacao.py
   ```

   O uv lê o bloco, cria um ambiente isolado em cache e roda o script de forma transparente.

## Roteiro de adoção

1. **Imediato:** troque `pip install` por `uv pip install` e `python -m venv` por `uv venv` nos projetos existentes, para acelerar instalações e builds.
2. **Curto prazo:** passe a gerenciar as versões do Python com `uv python install` e `uv python pin`, dispensando o `pyenv`.
3. **Médio prazo:** converta os projetos novos para `uv init`, `uv add` e `uv.lock`.
